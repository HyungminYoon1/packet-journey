## 연결 작전

첫 화면에서 목표와 조건을 읽고 판단을 선택합니다. 결정의 결과를 재생하거나 한 단계씩 확인하면 다음 판단이 열립니다. 잘못된 판단도 시간과 조치 예산을 사용하며, 장애가 남으면 해당 단계에서 복구를 시도해야 합니다.

| 작전 | 목표와 주요 판단 |
| --- | --- |
| 복합 장애 복구 | 오래된 응답 대신 최신 자료 요청 → 사용 가능한 DNS 리졸버 → 경로 선택 → 만료된 인증서 갱신 → 전송 |
| 혼잡 구간 돌파 | 유효한 DNS 캐시를 사용하고 홉 수·RTT·대기열·유실을 함께 비교해 마감 안에 응답 완성 |
| 경로와 인증 | 끊긴 경로 우회, TLS 검증, 누락 조각 재전송을 구분해 복구 |
| 저장본 구출 | 모든 경로가 끊긴 상태에서 저장된 자료 열기. 이 목표는 최신 서버 응답을 요구하지 않음 |

각 작전은 조건 01/02/03으로 재현할 수 있습니다. 조건에 따라 주소 캐시 TTL, 응답 캐시, 인증서, RTT, 대기열, 유실 번호와 응답 조각 수(6/8/10개)가 달라집니다. ‘다른 조건으로 도전’은 다음 조건으로 순환합니다.

- 경로 A/B/C는 각각 2/3/4개의 논리적 중계 홉입니다. 짧은 경로에도 혼잡이나 단절이 있을 수 있습니다.
- 일괄 전송은 조각당 4 ms, 간격 전송은 조각당 12 ms이며 대기열을 ¼로 줄이고 별도의 고정 유실 조건을 적용합니다.
- ACK된 조각과 LOST 조각을 구분하고, 누락 조각만 재전송하거나 전체를 다시 보낼 수 있습니다. 조각을 무시하면 완료되지 않습니다.
- 경로 재선택은 기존 연결·TLS 검증·수신 조각을 초기화합니다. 새 경로에서 연결과 인증부터 다시 진행합니다.
- 최신 응답 목표에서는 오래된 응답으로 완료할 수 없습니다. 저장본 열기 목표는 캐시를 사용해 네트워크 전체를 생략할 수 있습니다.

일반 모드는 12회 판단과 작전별 시간 예산, 1회 힌트를 제공합니다. 하드 모드는 판단 7회, 일반 시간 예산의 70%, 힌트 없음입니다. 시간 또는 조치 예산을 초과하면 다시 도전해야 합니다. 완료한 판단은 조치 한도에 도달했더라도 시간 예산 안이면 인정됩니다.

완료 점수는 100점에서 잘못된 조치당 15점, 힌트 사용 시 20점을 차감하고 최저 10점입니다. 패킷 유실 자체는 오답으로 감점하지 않습니다. 시간과 조치 횟수는 별도로 비교합니다. 조건·난이도별 최고 점수는 페이지 메모리에만 남습니다. 재생은 판단을 다시 적용하거나 시간을 추가하지 않습니다.

경로 표시, 누적 ms 요청 기록, 조각별 ACK/LOST/재전송 표시와 결정별 시간 막대로 원인을 비교합니다. 이전 판단의 요청 기록도 펼쳐볼 수 있습니다. 재생 속도는 모델 시간과 독립적입니다.

## 네트워크 진단

작전 선택에서 **캐시 만료 진단** 또는 **재시도 연쇄 진단**을 고릅니다. 각 진단은 조건 01/02/03과 일반/하드를 지원합니다. 기록 재생 속도는 가정 시간에 영향을 주지 않습니다. 마지막 원인 선택까지 맞혀야 완료됩니다.

- 캐시 만료: 처음에는 응답 나이 200 ms, max-age 1/2/3초입니다. 만료 전 저장본을 표시하고, 시간을 만료 경계까지 진행합니다. must-revalidate 조건의 만료된 응답은 ETag로 확인해야 합니다. 조건 01/03은 본문이 같아 304 후 저장 본문 v1 재사용, 조건 02는 내용이 바뀌어 200 후 v2 교체입니다. 본문은 만료만으로 지워지지 않습니다. DNS 캐시 제거와 확인 없는 재사용은 원인을 해결하지 못합니다.
- 재시도 연쇄: GET 클라이언트 3개, FIFO 서버 처리 슬롯 1개, 작업당 120/160/200 ms, 두 계층의 대기 한도 80/100/120 ms입니다. 각 계층이 최대 3회 시도하고 시간 초과가 서버 작업을 취소하지 않아 총 27개 작업, 최대 대기 24개가 생깁니다. 늦은 응답은 실제로 처리되지만 호출자 완료로 인정되지 않습니다. 게이트웨이 재시도를 끄고 클라이언트 대기 한도를 전체 원래 요청 처리 시간보다 1 ms 길게 잡으면 GET 3개만 접수, 최대 대기 2개, 수신 3/3으로 바뀝니다. 기존 정책 반복과 대기 한도만 두 배로 늘리기도 계산해 실패·중복을 보여줍니다.

각 비교 요청군은 서버 대기열이 비워질 때까지 관찰한 뒤 시작합니다. 이전 대기열에 새 요청을 얹은 결과로 표시하지 않습니다. 시간은 가정값이며 실측·실제 요청·기기 설정 변경을 수행하지 않습니다. 재시도 지터, 병렬 서버, 작업 취소 전파와 실제 Date/Age 보정은 생략합니다.

## 기기 완료 기록

오답·힌트 없이 끝까지 수행한 항목만 독립 완료로 저장합니다. 총 42개(기초 6 + 기존 작전 24 + 진단 12)이며 조건·난이도별 중복 완료는 한 번만 셉니다. 점수·전체 요청 기록은 계속 세션 메모리에만 남습니다. 힌트/오답이 있어도 완료 결과와 점수는 볼 수 있습니다.

- `packet-journey-achievements-v1`: 버전과 알려진 완료 항목 ID만 저장합니다. 방문·힌트·부분 진행·예시·재생으로 완료를 만들지 않습니다.
- `web-lab-progress-v1`: `{version:1,apps:{"packet-journey":{completed,total,updatedAt}}}` 형태의 최소 요약을 실제 완료 때 갱신합니다. durable ID 목록을 다시 읽어 수를 계산하며, 시각은 그 완료 때의 현재 ISO 값입니다. 이름·시드·행동·파일·요청 기록·점수는 없습니다.
- 15개 서비스 ID 허용목록, 정수 `0 <= completed <= total <= 1000`, 정확한 필드·ISO 시각·버전, 최대 8192자 JSON을 검사합니다. 잘못된 데이터나 저장 거부·용량 초과는 실패를 알리고 진행을 계속합니다. 잘못된 공용 요약은 덮어쓰지 않습니다.
- **완료 기록 지우기**는 이 앱의 완료 키와 요약 항목만 제거합니다. 다른 앱이나 다른 저장 키는 보존합니다. 갤러리 공유는 같은 origin에서만 동작하며 서로 다른 로컬 포트는 저장소를 공유하지 않습니다. 클라이언트 저장은 순위·학습 능력 판정이나 변조 방지용이 아닙니다.

## 6개의 기초 사건

1. **사라진 주소**: DNS 실패에서 연결이 시작되지 않은 이유를 찾습니다.
2. **연결 뒤의 오류**: HTTP 500 응답과 연결 실패를 구분합니다.
3. **끊어진 연결**: DNS 캐시만으로 인터넷 연결을 복구할 수 없음을 확인합니다.
4. **오프라인의 역설**: 최신 페이지 캐시를 비워 네트워크 없이 열린 이유를 검증합니다.
5. **기억된 주소**: 유효한 DNS 캐시를 비워 조회 실패가 가려진 이유를 확인합니다.
6. **가장 짧은 여행**: DNS 캐시와 최신 페이지 응답 캐시가 생략하는 단계를 비교합니다.

먼저 요청을 끝까지 조사해야 조치를 선택할 수 있습니다. 오답은 이유를 설명하며 조건을 바꾸지 않습니다. 정답을 선택하면 조건을 바꿔 재생하고 전후의 단계 수·시간·결과를 비교합니다. 캐시 제거 사건에서는 요청 실패를 드러내는 것이 학습 목표이지 연결 복구가 아닙니다.

사건별 100점에서 오답당 15점, 힌트 사용 시 20점을 차감하며 최저 10점입니다. 이번 세션에서 사건별 최고 점수만 합산합니다. 언제든 다른 사건으로 이동하거나 다시 풀 수 있고, 전역 순위나 사용자 능력 판정을 하지 않습니다.

## 자유 실험

기존 캐시·상황·왕복 지연·재생 속도 설정을 유지합니다. 자동 재생·일시정지·한 단계씩·재시작, 요청 기록과 DNS/TCP/TLS/HTTP/캐시 설명을 지원합니다.

- 정상 첫 요청: 브라우저 → DNS → TCP → TLS → HTTP 요청/응답 → 렌더링
- 유효한 DNS 캐시: 주소 조회만 생략; 연결과 HTTP 요청 필요
- 최신 페이지 응답 캐시: 서버 재검증 없이 사용할 수 있는 응답을 전제로 네트워크 전체 생략
- DNS 실패: TCP와 HTTP 전에 중단
- HTTP 500: 연결 이후 받은 서버 오류 응답
- 오프라인: 페이지 캐시가 없으면 브라우저 단계에서 중단

## 모델의 범위

HTTPS over TCP를 단순화했습니다. 지도는 처리 단계와 미리 정한 논리적 중계 홉을 표시합니다. ‘시뮬레이션’ 표시와 펼쳐보는 원리 설명으로 범위를 구분합니다. 실제 요청·DNS 조회·기기 설정 변경을 수행하지 않습니다.

기초 사건과 자유 실험은 주소/캐시 확인·렌더링과 서버 처리 시간을 정해 두고, DNS·TCP·TLS에 각각 왕복 지연을 적용합니다. 기본 정상 요청 390 ms, DNS 캐시 312 ms, 최신 페이지 캐시 33 ms입니다.

연결 작전은 별도의 사건 조건과 순수 상태 전이를 사용합니다. 경로 연결은 RTT의 절반을 홉에 나누고 반환에 나머지 절반을 사용하며 정수 반올림 차이가 있습니다. TLS 검증은 RTT 한 번, 갱신은 110 ms를 추가합니다. 전송 시작 시간은 RTT + 대기열이고, 각 응답 조각 시간과 유실 시 고정 대기 2 RTT를 더합니다. 최초 전송의 유실 번호는 정해져 있으며 재전송은 한 번에 성공합니다. 저장본 표시는 캐시 사용 3 ms + 렌더링 25 ms입니다.

기존 작전의 DNS TTL과 응답 최신성은 조건으로 주어집니다. 새 캐시 진단에만 가정 시간의 만료 시계·조건부 HTTP 재검증이 있습니다. 실제 TCP의 혼잡 윈도, 적응형 RTO, ACK 전송 세부, 연결 재사용·재귀 DNS·CDN·HTTP/3·병렬 리소스는 생략합니다. 클라이언트 점수는 조작 방지나 학습 능력 판정용이 아닙니다.

## 실행·검증·배포

Node.js 22 이상, 패키지 설치 없이 실행합니다.

```sh
git clone https://github.com/HyungminYoon1/packet-journey.git
cd packet-journey
npm run dev -- 0
npm test
npm run check
```

출력된 Local 주소를 엽니다. 0은 임시 포트를 자동 선택합니다. 53개 Node 테스트는 기존 요청/기초 14개, 연결 작전/전송 15개, 진단 모델 11개, 저장 경계 8개, DOM·타이머 더블 UI 5개입니다. 기존 24개 작전과 새 12개 진단 조합의 완료 가능성, 실패 선택, 시간/조치 예산, 저장/삭제/복원과 재생을 확인합니다. UI 더블은 실제 브라우저 렌더링이나 WebMCP 런타임 검증이 아닙니다. [검증 기록](docs/verification.md)에 로컬 테스트·실제 브라우저·원격 CI·공개 배포를 구분합니다.

Pages Source는 GitHub Actions입니다. main 푸시 후 테스트·정적 검사 통과 시 dist만 배포하며 모든 자산은 상대 경로입니다.
